# 🛒 Campus Cart — Full-Stack Shopping Application

Campus Cart is a full-stack web application designed to provide a convenient and user-friendly shopping experience for the campus community. It brings together frontend design, backend processing, and database management to support product browsing and shopping-related operations.

## 📖 About the Project

Campus Cart is developed to demonstrate how a full-stack shopping application works. The frontend provides an interface for users to interact with the application, the backend handles application logic and requests, and the database stores and manages application data.

The project provides practical experience in building and connecting different components of a web application.

## 🎯 Problem Statement

Managing and presenting products through a simple, organized, and accessible shopping interface can be challenging when information and operations are handled manually. Campus Cart aims to provide a centralized digital platform for product browsing and shopping-related activities.

## 🎯 Objectives

## 🏗️ System Architecture

Campus Cart follows a full-stack architecture consisting of three main layers:

1. **Frontend Layer:** Displays the user interface and collects user interactions.
2. **Backend Layer:** Receives requests, applies application logic, and communicates with the database.
3. **Database Layer:** Stores and retrieves the data required by the application.

### Architecture Flow

User → Frontend → Backend/API → Database

The response travels back from the database through the backend to the frontend, where the result is displayed to the user.

## 🔄 Project Workflow

1. The user opens the Campus Cart application.
2. The frontend displays the available interface and product information.
3. The user performs an action, such as browsing or selecting a product.
4. The frontend sends a request to the backend when required.
5. The backend processes the request and interacts with the database.
6. The database returns the requested information.
7. The backend sends a response to the frontend.
8. The frontend displays the result to the user.
